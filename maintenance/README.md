# Исправления — 2026.11.12.3 (v20)

В v20 interaction_fix.py добавляет короткое визуальное подтверждение заголовка
экрана выбора, чтобы пропуск OCR не отменял наведение на четыре карточки.
Позиция мыши и нажатие/отпускание ЛКМ отправляются атомарными событиями
с абсолютными координатами виртуального рабочего стола. Это учитывает
возврат курсора в центр окна между проверкой кадра и нажатием.
При потере фокуса кнопка мыши отпускается на текущем месте.
В latest_choice_click.json сохраняется причина отмены клика.

Повторный Enter в обоих режимах проигрыша использует удержание 6 мс и паузу
4 мс. Пачка ограничена 250 мс, ход перепроверяется каждые 75 мс,
фокус и остановка — перед каждым нажатием. test_interaction.py проверяет
код из EXE с имитацией возврата курсора в центр, пропуска OCR, потери фокуса
и завершения хода. В тесте выполнено более 20 нажатий за 250 мс.
Живой выбор карточки на ПК пользователя в этой проверке не выполнялся.

Проверка выполняется командой test_interaction.py FIXED_EXE SOURCE_DIRECTORY.
SOURCE_DIRECTORY указывает на локальный outputs/Bukvoed-v12 с зависимостями
и исходными типами Win32. Кадр первой буквы берётся из локальной папки work.

В v19 перед определением травы выполняется небольшой наклон камеры к земле.
Свежий кадр считывается после завершения движения камеры. Подъём включён
в откат ракурса, поэтому неудачные попытки не накапливают наклон.

В v18 направление выбирается по самой траве. Прежний тест древесины
противоположной стороны не проходил, когда камера отдалялась и стол становился
маленьким. Повторные попытки продолжали отдалять камеру и больше не доходили
до движения. Новая процедура находится в chair_fix.py. Она сначала идёт,
прыгает при подтверждённом отсутствии смещения, сохраняет отправку виртуальных
клавиш и снятие фокуса ввода из v17.

При видимой траве камера остаётся на месте. Поиск состоит из трёх независимых
небольших отклонений с возвратом после каждого неудачного. Колесо при поиске
не используется. Относительное движение мыши масштабируется по клиентской
области окна. Ракурс восстанавливается также после неудачной попытки возврата.

Проверки v18 выполняют код из собранного EXE. Десять кадров записи зависшего
лобби проверены в 1280×720, 1920×1080, 2560×1440 и 2560×1600. Дополнительно
проверены обычный шаг, прыжок при отсутствии движения, переход к партии,
ограниченный поиск камерой, отпускание клавиш, остановка и запуск из лобби.
Встроенная проверка EXE прошла с GUI и Windows OCR.
Живая партия на втором ПК в этих проверках не участвовала.

Для проверки движения v18 первым аргументом test_chair.py служит EXE v17,
вторым — проверяемый EXE. Третий аргумент необязателен и задаёт локальную
видеозапись зависшего лобби. Проверки test_restart.py и test_startup_input.py
по-прежнему сравнивают базовую версию 2026.11.08.14 и проверяемый EXE.

## История v17

В v17 исправлены две ошибки, оставшиеся в v16:

- Рабочий цикл проверяет лобби сразу после «Пуска», даже если до этого
  не видел своего хода. Раньше старт уже за столом мог навсегда ждать хода.
- Перед движением снимается фокус с поля ввода предыдущей партии.
  Только в процедуре перезапуска WASD и Space отправляются с виртуальными
  кодами клавиш; ввод слов использует прежнюю процедуру. Клавиша
  отпускается также при остановке, смене фокуса и ошибке отправки.

Живая проверка 10.11.2026: запуск из лобби, персонаж прыгнул и отошёл,
вернулся к стулу; игра показала «Ждём второго игрока». В логе:
смещение сцены 39.7, отклонение после возврата 11.7, результат `returned`.
Проверочный запуск остановлен после подтверждения возврата.
Полная партия с другим игроком не выполнялась.

`test_startup_input.py` воспроизводит блокировку прежнего рабочего цикла
и проверяет исправленный цикл до первого своего хода; отдельно проверяет
пакеты нажатия, удержания и отпускания WASD/Space и сохранность прежнего
ввода слов. Остальные проверки v15/v16 также проходят.

В v16 восстановлены процедура движения и определение направления из выпуска
2026.11.08.9, коммит `0cdeacde42f240054bed0fa1fc28badf4a69ace9`.
Это оригинальный код из предыдущего EXE: прыжок, отход от стула,
движение обратно и проверка возврата. Убрана обёртка, которая после неудачи
откручивала камеру обратно и повторяла поиск из того же ракурса.

Восстановленный код, клавиатурный ввод и ввод мыши проверяются сравнением
с кодом из Git. Новые проверки `test_chair.py` выполняют реальную процедуру
из собранного EXE с имитацией кадров и ввода: успешный возврат, переход
к партии, поиск камерой, отсутствие движения и остановка. Они не отправляют
нажатия в Roblox. Живая проверка v17 описана выше.

## Повторная сборка

Нужен Python 3.13. Исходный EXE берётся из коммита 08ffd6a:

```python
import pathlib, subprocess
pathlib.Path('base.exe').write_bytes(subprocess.check_output([
    'git', 'show', '08ffd6a:app/BukvoedApp.exe'
]))
```

```text
python maintenance/release_patch.py base.exe fixed.exe
python maintenance/test_restart.py base.exe fixed.exe [папка_кадров]
python maintenance/test_chair.py base.exe fixed.exe
python maintenance/test_startup_input.py base.exe fixed.exe
```

Для тестов нужны NumPy, OpenCV и Pillow под Python 3.13. Записи и кадры
с компьютера пользователя в репозиторий не включены. SHA-256 базового EXE
проверяется перед изменением; заменяется только точка входа bot в архиве
PyInstaller. Загрузчик EXE и остальные архивные элементы сохраняются.
Для сборки v16 нужна полная история этого Git-репозитория: процедура движения
берётся из указанного коммита, SHA-256 прежнего EXE проверяется до извлечения.

После замены app/BukvoedApp.exe необходимо обновить его SHA-256
в manifest.json и номер выпуска. Корневой Bukvoed.exe при следующем
запуске скачает изменившееся приложение.
